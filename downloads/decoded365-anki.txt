<b>Access control entry</b><br><i>SharePoint</i>	<b>Beginner</b><br>An access control entry is one line on a guest list: it names a person or group and says what they may or may not do with something.<br><br><b>Maker</b><br>Each entry either grants or denies permissions to a user or group. SharePoint builds on the Windows security model, so you meet these entries when permissions are inherited or checked. Entries are collected into an Access control list.<br><br><b>Architect</b><br>An entry sits in an object's discretionary list (DACL), where it grants or denies access, or in its system list (SACL), where it says which security events to audit or sets the Windows Integrity Level. The order and type of entries decide the final access result.<br><br><small>Decoded365, CC BY 4.0. https://sandeep-fed.github.io/Decoded365/terms/access-control-entry/</small>	decoded365 sharepoint ga
<b>Access control list</b><br><i>SharePoint</i>	<b>Beginner</b><br>An access control list is the full guest list for a door: every person or group and what each is allowed to do.<br><br><b>Maker</b><br>It is the set of access control entries for a whole object, a group of its properties, or a single property. It defines the access given to each security principal, such as a user or a group.<br><br><b>Architect</b><br>In Windows-based systems the list can be attached at several levels of granularity. Whenever a principal asks for access, the system walks the entries to decide the result, so the list is the unit that security checks are evaluated against.<br><br><small>Decoded365, CC BY 4.0. https://sandeep-fed.github.io/Decoded365/terms/access-control-list/</small>	decoded365 sharepoint ga
<b>Access URL</b><br><i>SharePoint</i>	<b>Beginner</b><br>An access URL is the address the search robot uses to reach a file or page when it collects information for search.<br><br><b>Maker</b><br>When search crawls content it needs an internal address for each item. That is the access URL, and it is not always the address people see in the search results. Keep the two apart when you troubleshoot why an item is missing.<br><br><b>Architect</b><br>The access URL is the internal URL a crawler uses to identify and fetch an item. It can differ from the display URL shown to users, and the crawl log records results against the display URL. See Crawl log.<br><br><small>Decoded365, CC BY 4.0. https://sandeep-fed.github.io/Decoded365/terms/access-url/</small>	decoded365 sharepoint legacy

Actions can be provided by services such as MCP servers or REST APIs, and in Copilot Studio they can also be connectors or flows.<br><br><b>Architect</b><br>Tool calling invokes configured MCP or API actions. You define the inputs and outputs, the authentication and any confirmations, and make the service behave reliably. Ask for confirmation before an action changes data, and give the identity that the action uses only the access it needs.<br><br><small>Decoded365, CC BY 4.0. https://sandeep-fed.github.io/Decoded365/terms/agent-action/</small>	decoded365 copilot ga

It is one of the social features of SharePoint.<br><br><b>Architect</b><br>The feed is built from user-profile and social data, so what appears depends on what a person follows. You can put the steps in any order, but together they form one activity flow.<br><br><b>Architect</b><br>The flow is the runtime counterpart of its definition: action instances and Activity model instances are sequenced to make a single flow. Instead of rebuilding the same steps each time, you reuse the model inside a bigger Activity flow.<br><br><b>Architect</b><br>Models are building blocks: an Activity flow can mix single actions and activity model instances in any order.
